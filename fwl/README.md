# FWL — Firewall Language

`fwl` is the v0.1 compiler for the Firewall Language at the heart of `f`. It
takes a `.fw` source file describing rules and produces a verifier-accepted
XDP/eBPF program that runs at line rate in the kernel.

The full language spec lives in [`docs/FWL_V01_SPEC.md`](../docs/FWL_V01_SPEC.md);
the build methodology in [`docs/F_DEVELOPMENT_METHODOLOGY.md`](../docs/F_DEVELOPMENT_METHODOLOGY.md).

**Status:** v0.1 surface complete. 88 unit tests + 62 corpus cases pass.
On a Linux host with `CAP_BPF` (or root) every behavioral corpus case runs
through `BPF_PROG_TEST_RUN`; in unprivileged dev environments the BPF
oracle skips cleanly while spec + interpreter + clang-compile still gate
regressions.

## Install

```sh
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
```

Requires Python 3.11+, clang (for BPF compilation), and libbpf 1.x (only
when loading programs into the kernel via `fwl test` on a real host).

## Quick start

```sh
cat > my.fw <<'EOF'
@xdp(eth0)

# Allow established outbound TCP, drop internal addresses, default deny
drop if pkt.src_ip in [10.0.0.0/8, 192.168.0.0/16]
allow if pkt.proto == tcp and not pkt.tcp.syn
allow if pkt.proto == tcp and pkt.dst_port in [80, 443]
default drop
EOF

fwl parse my.fw       # print the AST
fwl check my.fw       # parse + semantic check, no codegen
fwl compile my.fw     # emit BPF C to stdout
fwl test corpus/      # run a corpus of .pkt cases
```

## What v0.1 supports

- Hook: `@xdp(<interface>)` (single attach point).
- Actions: `allow`, `drop` (terminal), `log`, `count <name>` (non-terminal).
- Default rule: `default allow|drop` as the explicit final rule.
- Fields: `pkt.proto`, `pkt.{src,dst}_ip`, `pkt.{src,dst}_port`,
  `pkt.tcp.syn`, `pkt.tcp.ack`.
- Operators: `==`, `!=`, `<`, `>`, `<=`, `>=`, `in`.
- Operands: integer (decimal/hex), IPv4 dotted-quad, CIDR, list, port range,
  CIDR list.
- Composition: `and`, `or`, `not`, parens (and binds tighter than or).
- One stateful primitive: `rate_limit(N, per=<field>)` as a `limited by`
  modifier on any rule.

Anything else is deferred to v0.2+ (see the spec's "What Is Not in v0.1"
section).

## Verification model

Every language construct is verified against three independent oracles
before it ships, per the methodology document:

1. **Spec** — human review at corpus authoring time. The runner sanity-
   checks that each `.pkt` declares the fields it needs.
2. **AST interpreter** — `fwl/interpreter.py` walks the parsed AST against
   a decoded packet dict. Shares only AST node definitions with the
   emitter, so disagreements diagnose real compiler bugs.
3. **BPF runtime** — `fwl/bpf_runner.py` compiles via `clang -target bpf`,
   loads via libbpf, populates any rate_limit maps from `.pkt` state, and
   runs via `BPF_PROG_TEST_RUN`. Requires `CAP_BPF` (or root). When
   unavailable the runner still compiles the emitter output (catching
   structural bugs) and skips the actual run with an explicit message.

The corpus under `tests/corpus/` is organized by phase:

```
tests/corpus/
  00_smoke/                # @xdp + allow only
  01_proto_match/          # pkt.proto == <kw>
  02_multi_rule_default/   # rule sequencing + default
  03_fields_composition/   # IP/port fields, in/CIDR/range, and/or/not
  05_rate_limit/           # rate_limit modifier with .pkt state
  06_log_count/            # log + count actions
  07_edge_cases/           # boundary values, hex, deep nesting
```

Run the whole corpus:

```sh
fwl test tests/corpus/                # interpreter + clang-compile
sudo .venv/bin/fwl test tests/corpus/ # add live BPF_PROG_TEST_RUN
```

Module-level pytest unit tests live under `tests/unit/`:

```sh
.venv/bin/python -m pytest tests/unit/
```

## .pkt format

A test case is a YAML document:

```yaml
name: "rate_limit fires while bucket is below threshold"
source_fw: |
  @xdp(eth0)
  drop if pkt.proto == tcp and pkt.dst_port == 22
       limited by rate_limit(10, per=src_ip)
  default allow

# Optional: pre-populate rate_limit buckets keyed by rule index.
# Here rule 0's bucket for 1.2.3.4 is at count 5 (under N=10).
state:
  rate_limit:
    0:
      "1.2.3.4": 5

test_packet:
  builder: tcp(src_ip="1.2.3.4", dst_port=22)

expected:
  compiles: true
  bpf_action: drop  # under threshold => drop rule fires
```

The builder mini-language is parsed (not eval'd Python) — corpus content
can be safely generated by AI agents without RCE risk. Supported
builders: `tcp(...)`, `udp(...)`, `icmp(...)`. Sensible defaults are
filled in for fields not specified.

Cases with `expected.compiles: false` skip the action check entirely;
the interpreter and BPF oracles verify that the program is rejected.

For stateful rate_limit cases the runner translates the `state:` block
into byte-packed entries written via `bpf_map_update_elem` before
`BPF_PROG_TEST_RUN`, so the BPF oracle and the interpreter both see the
same starting bucket counts.

## Directory layout

```
fwl/fwl/
  ast.py              AST dataclasses
  parser.py           Lark LALR + transformer
  analyzer.py         Semantic pass: protocol guards, threshold, counter limit
  interpreter.py      AST oracle
  emitter.py          BPF C generator
  pkt.py              .pkt loader + packet builder mini-language
  bpf_runner.py       clang + libbpf BPF_PROG_TEST_RUN harness
                        (with per-CPU map pre-population)
  runner.py           Three-oracle test harness
  cli.py              Click CLI
  errors.py           Source-spanned error types
  grammar.lark        v0.1 grammar reference
fwl/examples/
  ssh_brute_force.fw      SSH SYN flood throttle + counter
  web_server_ddos.fw      Per-source flood guard + HTTP/HTTPS allow
  internal_network.fw     RFC1918 trust + service ports + log unsolicited
fwl/tests/
  corpus/             .pkt cases organized by phase (62 cases)
  unit/               module-level pytest tests (88 tests)
```
